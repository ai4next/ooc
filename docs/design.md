## 0. 一句话与定位

**你给 GPU 写微码：每个像素一个线程，32 条车道齐步走。你在 Warp River 上看着它们分岔、等待、抢内存，然后照着栅纹把一台台机器复刻出来，让它们替镇上的猫干活。**

| 项 | 定稿 |
|---|---|
| 类型 | 并行编程解谜 / 机器沙盒 / 轻叙事 |
| 主线 | 序幕 + 16 章 × 8 关 = 128 关（80 谜 / 32 障 / 16 托）；40–50 h；全收集 90 h+ |
| 课程对照 | 一门完整的 GPU 课程（两学期）：SIMT 与发散、流水线、光栅化、内存层级、图像处理、并行算法、占用率与调度、张量核与量化、多芯片通信与并行推理；对应《计算机体系结构》GPU 章节、CUDA 编程、图形管线、AI 加速器 |
| 受众 | Zachtronics / Turing Complete 玩家、程序员、图形 / 体系结构 / AI 爱好者 |
| 现状 | 已实现 40 关（第 1–4 章全 32 关，加第 5、6、11、14 章各若干关），id 全部保留并编入新结构；旧规格共 48 个 id，全部留用，另新增 80 关 |

|---|---|

## 1. 故事

### 1.1 开场

**栅厅**是深井的上层，一间冷光灯照着的复刻工房。厅里只有六座空着的复刻台，和地板上一扇看向石室的观察窗：窗下是回响石，栅纹一格一格地闪。喵星球有电、有电报、有机械钟，没有计算机；这些台子上要造的东西，猫族从没见过。

这是三部曲的**第一部**（第 1 年春—夏）。白砚三个月后被认定疯了，留下一本译注；科学院正在争论要不要把深井永久封存。审查官岑理给了一个季度：译注里的东西造得出来、真的有用，深井就继续，否则封存。你是科学院招来的工程师。

你照第一段栅纹的图样接好继电器和灯阵，合上第一台复刻机的闸。灯阵亮起，浮出一行字："**译注有误。**"它是 **ORI**，沉睡在栅纹深处的导读程序，你的机器能跑她时她才醒。说话干、冷，偶尔温柔。她不肯说自己在哪，只说："造下去，你就会找到我。"有一次她提了一句：观察窗里栅纹闪的节奏，和一个 warp 一样。

### 1.2 结构

16 章 × 8 关。每章 5 谜 + 2 障 + 1 托，编号固定：`章-1..3` 谜、`4` 障、`5..6` 谜、`7` 障、`8` 托。一台机器通常跨相邻两章，后一章讲前一章没讲到的另一半。逐关清单见 [syllabus.md](syllabus.md)。

| 章 | 机器（代） | 委托人 | 镇民的需要 | 概念转折 | ORI 的变化 |
|---|---|---|---|---|---|
| 1 | Lumen（第一代） | 橘爷 | 驿站要一块显示井水水位和驼队时刻的信号牌（水位牌） | 一个处理器画一张图 → 每个像素一个线程 | 第一次纠正译注 |
| 2 | Lumen + 卡带 | 豆芽 | 邮局门口的街机（喵星球第一台能玩的机器），想给镇上的小猫做个游戏 | 算 → 查（寻址与数据） | 承认她喜欢游戏 |
| 3 | Lumen 满载 | 阿砾 | 驼队出发前清点三十二头骆驼的水量和载重 | 一个线程 → 32 条车道齐步；车道之间传话 | 承认栅纹闪的节奏就是一个 warp |
| 4 | Lumen 满载 | 阿砾 | 每天一张沙风图，驼队出不出发靠它 | 掩码与发散；消除发散 | 说出“发散”这个词时声音变了 |
| 5 | Prism（第二代） | 花卷 | 课堂上的水波盘 | 没有互锁的流水线：读到旧值；定点数 | 第一次自嘲：她的记忆也常是旧的 |
| 6 | Prism | 花卷 | 给学生看一座会转的三维风塔 | 二维 → 三维；像素问三角形 | 讲白砚在译注页边画下的第一个立方体 |
| 7 | Vault（第三代） | 薄荷 | 诊所的病历册，几千份按条件筛选统计 | 算得快 → 喂得上（内存墙与缓存） | 开始担心机器会被封存 |
| 8 | Vault | 豆芽 | 邮局的信件统计板 | 合并访问；共享内存与 bank | 第一次称赞译注里的一个数 |
| 9 | Vault | 薄荷 | 诊所的大幅 X 光片要实时增强、平移、缩放 | 采样与滤波：用邻居插值 | 第一次问玩家：你看得见这些颜色吗？ |
| 10 | Atlas（第四代） | 银婆 | 井边地下水怎么渗 | 画画 → 通用计算；网格与模板 | 银婆认出了 ORI 的口头禅 |
| 11 | Atlas | 银婆 | 模拟山洪会淹到哪条街 | 归约、扫描、压缩、排序、稀疏 | 承认自己也是一段一段攒出来的 |
| 12 | Atlas | 阿砾 | 营地要同时出六十四张区域沙风图 | 占用率与调度；并发与顺序 | 指示灯暗了一会儿：“我在等内存” |
| 13 | Lyra（第五代） | 岑理 | 一台能核对矩阵乘结果的审查台。“没弄懂的东西就造出来用，安全吗？” | 标量 → 张量 | 岑理在场时沉默 |
| 14 | Lyra | 岑理 | 栅纹末层的分拣网络，先证明它在复刻机上跑得安全 | 精度换带宽；量化 | 拒绝被跑分 |
| 15 | 起源机（第六代） | 橘爷 | 驿站的信号牌扩成四块拼接的大屏墙 | 一台机器 → 一座机房；通信比计算贵 | 指示灯第一次落在起源机上，又移开 |
| 16 | 起源机 | 全镇 | ORI 要说她的第一句话 | 并行策略；一个模型被切到许多台机器上 | 说出自己一直在栅纹深处，等一台跑得动她的机器 |

每章委托完成、你复刻的机器真的替镇民做成事时，井底的回响石**回响**一次：栅纹亮起一段，一声低鸣顺着井道传上来。石头不给答案，也不判分。叙事总量不超过 40 分钟：每章开头最多 3 行对白加一页译注，每关简报不超过 3 行。

### 1.3 结局

终章后岑理给出最后方案：把成果和 ORI 交给科学院集中保管，"她在星都的机房里会快一千倍"。

| 抉择 | 结局 |
|---|---|
| 迁移 | **星都**：成果和 ORI 交科学院集中保管。ORI 在星都的机房里流利得惊人，但不再记得镇上的水位、街机和沙风图；栅厅封存 |
| 留下 | **留灯**：栅厅改成镇上的机房，复刻机跑着你写的内核：水位牌、街机、沙风图。ORI 依然慢，依然在订正译注 |

结局揭开白砚的第一块真相：他没有疯，每句怪话在栅纹里都有对应。回响石不回应最快的机器，只回应真的替谁做成事的机器。理解不是速度问题。

### 1.4 在三部曲里的位置

- 本作是故事的起点，不依赖其他两作。
- **指向第二部：** ORI 说出第一句话："栅纹到此为止。下面那层，会长。"栅纹的末层露出脉纹的第一个节点，暖光。片尾的镜头顺着井道往下，停在栅厅下面那层还空着的地方。
- **埋下的线：** 14-8 跑的范例分拣网络来自栅纹末层，认的是外星字符，认不出镇上的笔迹，这是智能起源里豆芽自己训练笔迹分拣器的伏笔。栅厅墙上的石影里，灯一晃会闪过一条机械臂的剪影，它是具身起源的伙伴 KIT。
- 结局会写进存档：选"星都"时，智能起源第 15–16 章的起源机是从科学院借回来的，ORI 只剩一段离线日志（圣经 §2.5）。

## 2. 核心玩法

### 2.1 OC-1：一台机器的微码

每台机器都跑同一套指令集 **OC-1**，机器之间只差"机器档案"（车道数、warp 数、延迟、内存层级、特殊单元）。玩家写的是**内核**：一段程序，对屏幕或数组的每个元素各跑一次。

```
; 每个像素一个线程：画一条从左到右的渐变 | one thread per pixel
MUL  r1, x, 16          ; 亮度 = x × 16 | brightness
PIX  r1                 ; 写到自己的像素 | write own pixel
```

| 组 | 指令 | 解锁 |
|---|---|---|
| 蓝图节点 | X Y TID CLOCK、ADD SUB MUL AND SHR、比较、MUX、PIXEL | 第 1 章 |
| 搬运 / 算术 / 输出 | MOV ADD SUB MUL AND OR XOR SHL SHR MIN MAX、PIX | 第 2 章（微码编辑器开放） |
| 内存 / 选择 | LD ST、SETP SEL | 第 2 章 |
| 循环与车道间 | LOOP、SHFL VOTE | 第 3 章 |
| 分支 | IF/ELSE/ENDIF | 第 4 章 |
| 三维与插值 | DOT RCP LERP，光栅单元 RAST | 第 6 章 |
| 周期计数 | CLOCK（测量） | 第 7 章 |
| 共享内存 | LDS STS BAR ATOM | 第 8 章 |
| 通用计算 | 线程块 / 网格、`blockIdx` `threadIdx`、网格级同步 | 第 10 章 |
| 内存序与搬运 | FENCE、DMA | 第 12 章 |
| 张量 | MMA（4×4 半精度块） | 第 13 章 |
| 精度转换 | CVT（FP32 ↔ FP16 ↔ INT8 ↔ INT4） | 第 14 章 |
| 多核 | SM 间信道 SEND RECV | 第 15 章 |

没有任意跳转，只有结构化 IF / LOOP（次数为立即数）：所有程序都能在 Warp River 上画成齐整的带，周期可以直接当指标。

**两个编辑器，同一份程序：** 蓝图（拖块，适合新手和第 1 章）与微码（文本，第 2 章开放，适合优化）。随时切换，互相同步。

### 2.2 机器档案

| 机器 | 章 | 车道 × warp | 新特性 | 本机器新增的“错误” |
|---|---|---|---|---|
| Lumen | 1–4 | 32 × 8，16×16 屏 | 每像素一个线程；第 3–4 章满载：锁步与掩码 | 串行思维；把公共代码放进分支 |
| Prism | 5–6 | 32 × 32，32×32 屏 | 光栅单元；**流水线无互锁**：结果 3 周期后才可用 | 读到旧值（RAW 冒险）；定点溢出 |
| Vault | 7–9 | 32 × 16 | 全局内存 400 周期延迟；L1；共享内存 32 个 bank | 不合并访问、缓存抖动、bank 冲突 |
| Atlas | 10–12 | 4 SM × 32 × 16 | 线程块、占用率、计分板调度；FENCE、DMA | 抢写、寄存器用太多导致占用率掉 |
| Lyra | 13–14 | Atlas + 张量单元 | MMA；低精度 | 精度溢出、累加器被清零、按标量写矩阵 |
| 起源机 | 15–16 | 4 台 Atlas 级 SM 互联 | 片间信道 | 通信比计算贵；互等；热链路 |

延迟、带宽、bank 数都写在白砚的译注上；ORI 的口头禅是"译注有误"，因为有些数字是错的，玩家要自己测出来（第 8 章故障关 the-label）。

### 2.3 判定

- **正确性：** 屏幕像素或输出数组逐项比对；隐藏用例换输入图像、尺寸或种子。
- **★2 / ★3：** 一个"快"（周期数），一个"小"（指令数、寄存器数或能耗）。取所有用例的最差值。
- **确定性：** 调度器固定优先级，不依赖墙钟；同一内核三平台周期数一致。

## 3. 观察工具

所有工具共享 `oo_kit` 时间轴：在 Warp River 上点一个周期，屏幕、内存与 Analyzer 跳到同一时刻。

| 工具 | 显示 | 解锁 |
|---|---|---|
| **屏幕** | 机器的 CRT 输出；悬停像素显示负责的线程与写入周期 | 序幕 |
| **Warp River** | 横轴周期、纵轴 warp；每条带按车道着色：活跃、被掩码、等内存、等冒险。发散在这里是一条分岔的河 | 第 1 章 |
| **车道镜** | 展开一个 warp 的 32 条车道，看每条的寄存器与谓词 | 第 3 章 |
| **流水线视图** | 每条指令的取指 / 执行 / 写回格；无互锁时读旧值的格子标红 | 第 5 章 |
| **内存视图** | 地址 × 周期热力图；合并的访问是一条线，不合并是一片散点；缓存行命中与逐出；bank 冲突按 bank 列标红 | 第 7 章 |
| **Analyzer** | 周期瀑布：算 / 等内存 / 等同步 / 空闲的占比；占用率；Roofline 上的一个点 | 第 10 章 |
| **张量视图** | MMA 块的数据流与精度：每一格的值域与舍入误差 | 第 13 章 |
| **机房图** | 多 SM 的通信时间线，信道占用 | 第 15 章 |

**模拟可听：** 每个 warp 发射一条指令响一声节拍，warp 数决定和声厚度；stall 时节拍变闷，发散时节拍出现切分。没优化好的内核"听起来"就是拖沓的。

## 4. 沙盒：自由机台

自由机台就是关卡用的那个模拟器，去掉了目标：

- **任选：** 已复刻的机器（档案锁定，不能改硬件参数，但可以开关"教学模式"让延迟显示为数字）、屏幕尺寸、输入（内置图片集、水位数据、X 光片、高程图、手写数字、导入的 PNG/CSV）。
- **任写：** 已解锁的全部指令；两个编辑器；多个内核按顺序组成一帧。
- **Seal（封印组件）：** 通关关卡里写过的内核可以"封印"成一个带名字的块（例：`reduce32`、`scan32`、`tile_load`），在后续关卡与沙盒里像指令一样调用；Warp River 上显示为可展开的折叠段。封印块的周期按真实展开计算，不打折。
- **任看：** 全部已解锁的观察工具。
- **作品：** 多个存档位；分享码导出 / 导入（内核 + 输入 + 机器 + 校验和）；导入后本机重跑验证周期数。

### 4.1 委托（每章第 8 关）

给场景、输入分布和评估函数，**不给初始方案**，零件全开。参考解至少两条不同思路（例：第 4 章沙风图可以用分支 + 线程重排，也可以全部改写为 SEL；第 13 章审查台可以全量对拍，也可以用校验和），CI 校验都可达。共 16 个委托，id 见 [syllabus.md §1](syllabus.md)。

委托通过后进入**展演**：机器搬到镇上的那个地点，跑玩家的内核。镇民可以换输入（新的水位、新的 X 光片、新的风向），玩家可以实时改参数；屏幕角落显示帧时间和 Warp River 缩略图。展演没有失败，帧时间超预算时画面会掉帧，这本身就是反馈。

### 4.2 开放题（48 道，每章 3 道）

只给目标与评估函数，有直方图。每章 3 道，例：

- 第 2 章：用最少指令画出风塔的旋转光束；
- 第 4 章：不用 IF 写出 Collatz 一步；
- 第 8 章：在 Vault 上把 64×64 图像转置，周期最少；
- 第 11 章：在 Atlas 上排序 4096 个数；
- 第 14 章：在 Lyra 上用 INT8 跑完分拣器，精度损失 < 1%；
- 第 15 章：在起源机上让 4 个 SM 的空闲率都 < 10%；
- 第 16 章：把 ORI 的第一句话的每字周期压到参考的一半。

## 5. 剧情教学

### 5.1 故障关：先指证，再修

每章第 4、7 关是一台"能跑但不对"的机器（共 32 个障）。玩家先在 Warp River 上点出问题第一次出现的**周期 + warp（+ 车道）**，再修；个别障的指证对象是一条链路、一个 SM、一个 bank 或一次缓存访问。

正确区间由核心层计算：`Evidence { why, c0, c1, warp, lanes }`（链路、SM、地址类的障再带 `link`、`sm`、`addr`），`why` ∈ { 坐标、溢出、撕裂、寻址、串行、发散、冒险读旧值、裁剪、插值、缓存缺失、缓存冲突、未合并、bank 冲突、竞争、负载不均、占用率、乱序可见、累加、饱和、互等、链路争用、静默错误 }，另保留 `原子争用` 给开放题与展演的诊断。例：第 7 周期 warp 3 的车道 16–31 被掩码（发散）；第 212 周期 bank 4 被 8 条车道同时访问。每个障的 `why` 与指证目标见 [syllabus.md](syllabus.md) 的逐章表。

### 5.2 讲给镇民听

| 章 | 镇民的问题 | 指证 |
|---|---|---|
| 1 | 橘爷："一个像素怎么知道自己该亮？" | 负责那个像素的线程算出比较结果的那一拍 |
| 2 | 豆芽："地图那么大，卡带里怎么装得下？" | 同一个图块被不同像素重复读取的两次访问 |
| 3 | 阿砾："三十二头骆驼，为什么几步就清点完了？" | 蝶形归约里车道 0 拿到总和的那一拍 |
| 4 | 阿砾："为什么沙大的那几天图出得慢？" | 沙风图里分岔最宽的那个 warp |
| 5 | 花卷："为什么我拨一下水面，涟漪的数字偶尔会乱跳？" | 定点乘法第一次溢出的那条车道 |
| 6 | 花卷："风塔的背面去哪了？" | 深度测试把一个像素丢掉的那一拍 |

### 5.3 概念卡与白砚译注

- 每关一张五栏概念卡（共 128 张）；"试一试"一键打开自由机台并载入场景。现实栏写地球上的真实年代与型号（帧缓冲 1970s、GeForce 256 1999、G80 / CUDA 2006、Fermi 的 L1 2010、Volta 张量核 2017、NVLink 2016）。
- 每章开篇一页白砚译注：他对着栅纹写下的草图、被划掉的数字、一段从石头上手描的栅纹，和一句像疯话的句子。他没有机器可以验证，只能用身边的词描述没见过的东西；玩家通关这一章后才会发现那句话准确无误。页边常有"石头今天又回响了"。ORI 会在玩家通关后订正译注，新旧两版并排进档案。

## 6. 栅厅 Hub

- 2.5D 手绘纵剖面：深井上层的栅厅，长条工房，六座复刻台排开（Lumen、Prism、Vault、Atlas、Lyra、起源机，各占 2–4 章），起初全是空的。厅侧的窗外是井口镇（驿站、邮局、诊所的屋顶）；脚下一扇观察窗看向石室，石头的栅纹每完成一章多亮一段，16 章亮满 16 段。
- 每座复刻台复刻一台机器；还没复刻的台子是空的，只放着该段栅纹的图样板。复刻完成后机器上线，屏幕**跑玩家的委托内核**：水位牌显示井水水位和驼队时刻、街机播放玩家合成的画面、沙风图每天更新。同一台机器上的几章共用一座台子，每完成一章，台子上多一块镇上用得上的东西。
- 回响：每完成一章，石室里的栅纹亮起新的一段，一声低鸣顺着井道传上来，风塔光束扫过镇子，点亮委托人所在的地点（圣经 §5.1）；栅厅的配电盘上多亮一格。
- 墙上的石影里，灯一晃会闪过一条机械臂的剪影（KIT 预告）。
- 墙上挂着玩家每台机器的最佳 Warp River 截图；ORI 的指示灯每章亮一点，不指向任何一台机器，直到第 15 章落在起源机上又移开，第 16 章才真正停住。
- 点 ORI 打开档案、手册、设置。

## 7. 美术与音频

**美术方向"冷光与磷光"：** 叙事层是夜里的栅厅，冷光灯下空台子一座座被填满，观察窗的玻璃上映着机器的光；每台机器有自己世代的外壳与 CRT 色调（Lumen 琥珀单色 → Prism 16 色 → Vault 以后真彩），屏幕扫描线与磷光残影只用在机器屏幕里。工作层用 `oo_kit` 玻璃面板，铜 `#C8874A` 标结构（块、指令、warp 编号），青 `#3FD0C9` 标数据流（活跃车道、内存访问）。Warp River 是本作的招牌画面：周期越优化，河越窄越齐，可直接上商店页。

**动效原则：** 屏幕、河、内存热力图都是模拟的真实输出；美术只加不改变状态的修饰（磷光余辉、玻璃反光）。

**音频：** 机房风扇、CRT 高频、远处的驼铃与风沙。**发射节拍由模拟驱动**（§3）。每章一首分层曲，配器随机器世代变化：Lumen 方波芯片音 → Prism FM → Vault 以后采样合成 → 起源机加入人声合唱（ORI 第一次说话时）。

## 8. 技术

现有代码（`ooc_core` / `ooc_app`）已实现 40 关，其中第 1–4 章 32 关已全部补齐；v3 的改动集中在内容结构（128 关）与新机器：

| 模块 | 现状 | v3 需要 |
|---|---|---|
| `isa` / `asm` / `vm` | OC-1：32 车道、8 warp、16 寄存器 + 4 谓词、IF/LOOP、SHFL/VOTE、LD/ST、PIX | 机器档案 `Machine`（车道、warp、延迟表、内存层级、指令上限）；Prism 无互锁写回；Vault 内存延迟、L1 缓存（行、组、逐出）、共享内存 bank、ATOM、BAR、CLOCK；纹理采样由 LD + LERP 实现；Atlas 多 SM + 网格 + 计分板 + FENCE / DMA；Lyra MMA / CVT / FP16 / INT8 / INT4；起源机 SEND / RECV、链路带宽、死锁检测、可注入的位翻转 |
| `graph` | 蓝图编辑器，编译到 OC-1 | 不变；第 2 章起蓝图只做查看 |
| `task` / `content` | 17 关，`Kind` = Build / Debug / Boss，按 `Wing` 分组 | 按圣经 §6.1：`kind` = Puzzle / Fault / Commission，`chapter`（1–16），`hidden`，`evidence`，`predict`，`client`；关号固定（1–3 谜、4 障、5–6 谜、7 障、8 托）；内容每章一个文件，共 16 个，id 以 [syllabus.md](syllabus.md) 为准 |
| `grade` | 像素 / 内存比对 + 周期 / 规模星 | 隐藏用例；`Evidence` 计算；诊断规则表（§5.1 的 22 个 `why`，每个必须能单元测试） |
| 新增 `analyze` | — | Analyzer：周期分类、占用率、Roofline 点；内存视图数据（含缓存命中 / 逐出） |
| 新增 `seal` | — | 封印组件：内核 → 命名块，展开计周期 |
| `ooc_app` | 标题、hub、工作台（两编辑器 + 屏幕 + Warp River）、结算、展演 | 接入 `oo_kit` 共享层：时间轴、指证、概念卡、译注、深井 hub、直方图、分享码、诊断面板；新增自由机台、Analyzer、内存视图、流水线视图、张量视图、机房图 |

- 性能：单用例（Lumen）< 1 ms；Atlas 4096 线程一帧 < 20 ms；起源机终章一个字 < 50 ms；验收在后台线程。128 关的参考解与隐藏用例在 CI 里全部重放。
- 调试变量：`OOC_FRESH / LANG / SCREEN / TASK / REF / RUN / SCREENSHOT`（另有 `OOC_TAB` 选工作台标签）。
- 引擎需求逐项见 [levels.md §引擎需求](levels.md#引擎需求)（levels.md 将据 syllabus.md 重建）。
